# Pane grid

## Plan

`docs/agents/plans/2026-09-25-014-pane-grid.md`

## Summary

The session area is a dockview layout. Each tab shows a session or terminal with its kind, title,
and status mark, and Close Tab on hover. Each pane header has `+` for the new menu. Dragging a tab
to a pane's edge makes a pane. Sidebar choices activate an existing tab or open one in the active
pane. The GUI state file holds dockview's serialized layout, which is restored on each connect,
dropping tabs whose session or terminal is gone. The session header, the terminal header, and the
saved selection are gone. The plan's goal is met without the split button and split shortcuts, which
the plan dropped.

Test guarantees:

- Gained owning tests: `tabs_close_when_their_session_or_terminal_is_gone`, table-driven over
  `goneTabs()`, and `has_snapshot_follows_the_connection`, which also checks that a reconnect waits
  for the new snapshot.
- Gained end-to-end tests: the ten in `panes.test.ts` that the plan names.
- Moved: `each session's tab keeps its own editor draft` and
  `a session's tab shows the session
  title` replace the tests for the editor draft and the session
  header; the delete and exit tests also check that the tab closes, and the terminal title test
  reads the tab.
- Lost: `the session header's + creates a session in its workspace and selects it`, with the session
  header. The pane's `+` opens a native menu, which WebDriver cannot drive.

## Departures from the plan

- `App` reads the saved layout on each connect and clears it on disconnect, instead of reading it
  once at startup. `Layout` remounts on reconnect and restores `saved`. A copy read at startup would
  bring back the startup layout and discard the changes made since.
- The mount-time `fit.fit()` in `TerminalPane` also checks for a nonzero size, not just the
  `ResizeObserver`. A restored terminal tab that is not active mounts hidden, and fitting it then
  would attach at one row.
- `Layout` sets `disableFloatingGroups`. Otherwise dockview's floating groups would be a second way
  to make a pane, and the plan says dragging to a pane's edge is the only way.
- `TerminalPane` takes a terminal ID instead of the `TerminalSummary`, since it no longer shows the
  terminal title.

## Decisions

- `Tab` is dockview's `defaultTabComponent`, so `addPanel()` does not name a tab component.
- Close Tab calls `preventDefault()` on pointer down and click, as dockview's own tab does.
- The status mark rules in `styles.css` are no longer scoped to `.row`, so the sidebar and the tab
  share them.
- The theme overrides use `.main .dockview-theme-dark` so they win over dockview's stylesheet
  whatever order the two load in.
- `Layout` disposes its listeners and resets the `DockviewApi` and the selection in `App` when it
  unmounts. It does not send an empty `set_visible` on unmount, so the Link replays the last visible
  sessions on reconnect until `Layout` sends a fresh set.
- `~/.local/state/ur/gui.json` did not exist, so there was nothing to delete.

## Manual verification

1. An ad-hoc check under `app/e2e/artifacts/` (not committed) used `TestEnvironment` and a second
   WebDriver session. Tabs were dragged with synthetic HTML5 drag events, since WebDriver cannot
   drive native drag and drop.

   ```sh
   pnpm -C app e2e   # builds target/e2e
   node app/e2e/artifacts/adhoc.ts
   ```

   Observed:
   - Clicking the session row opened a second tab in the terminal's pane.
   - Dragging the session tab to the pane's right edge made a second pane.
   - Clicking the terminal row and then the session row activated each existing tab in its own pane,
     and the sidebar highlight followed.
   - Closing the GUI and reopening it restored both panes with the same active tabs.
   - After dragging the session tab back to the center of the terminal's pane and switching tabs
     twice, `stty size` still printed `42 97`.
   - Close Tab on the terminal tab left the terminal row in the sidebar, and clicking the row
     reopened the tab.
   - `close_terminal` closed the terminal's tab.

2. Closing the only tab showed the watermark's "Select a session", centered in the session area.

Not checked: the pane's `+` and the workspace menu, since WebDriver cannot drive native menus.
Deleting a session closing its tab and the permission shortcuts answering only the active tab's
session are end-to-end tests.
