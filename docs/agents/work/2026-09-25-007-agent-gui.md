# Agent GUI

## Plan

`docs/agents/plans/2026-09-25-007-agent-gui.md`

## Summary

The core's `Link::run()` reconnects to the daemon, replays the desired set, and forwards events
under the `watch`, `session`, and `connection` event names. The GUI state file holds the GUI's
terminal and the selection, which the new `selection` and `select` commands read and save. The
webview has the sidebar with the Terminal row, the three empty states, the watch and session stores,
the transcript reducer, the thread, and the editor with Send and Stop. The end-to-end suite tests
the agent GUI against the fake server, which keeps its saved history in a file. The plan's goal is
met: the check in `docs/agents/todo.md` passes with Ox.

Test guarantees: the eleven vitest cases the plan lists and the five end-to-end tests in
`session.test.ts` own the new guarantees. The two terminal tests call `Gui.showTerminal()` and keep
their guarantees.

## Departures from the plan

- The desired set holds session IDs as `BTreeSet<String>`, not `BTreeSet<SessionId>`. `SessionId`
  has no `Ord`, and the app crate cannot name it without a dependency on the schema crate.
  `Request::Subscribe` takes the string back through `From<String>`.
- `Selection::Session` is a struct variant, `Session { session }`, not `Session(String)`: serde
  cannot internally tag a newtype variant holding a string.
- `reduce()` returns `undefined` for `session_removed`, and the session store drops the session
  then. The plan had the reducer return a `ThreadState` for every event.
- `App` draws nothing until `selection()` answers, rather than "Select a session". Otherwise the
  harness could click the Terminal row before the answer, and a `null` answer on first open would
  then unselect it.
- The watch store exports `workspaceSessions()` for the sidebar's per-workspace order, which is what
  `sessions_order_by_last_activity` tests; `reduceWatch()` keeps the daemon's order.
- Vitest is scoped to `src/**/*.test.ts` in `vite.config.ts`, since it otherwise picked up the
  end-to-end tests in `app/e2e/`, which run under `node --test`.

## Decisions

- Replayed requests run in spawned tasks, one each, so a `subscribe` waiting for a load does not
  delay event forwarding or the other replays.
- A selected session missing from the watch store shows as no selection at render time; the saved
  selection is not rewritten. It comes back when the session does.
- A `busy` prompt response shows "The session is busy." under the textarea.
- The harness's `Gui` gained `hasElement()`, `showTerminal()`, and the helpers the plan lists.
- The Stop test uses the `tool` script: the fake server does not handle `session/cancel`, so a
  running `hold` never ends, while a cancel during a permission request ends the turn.

1. The check in `docs/agents/todo.md` with Ox, driven through the WebDriver build in `target/e2e` by
   an ad-hoc script. The script starts a daemon in a temporary directory with an Ox config file,
   adds a workspace, creates a session with `ur new`, opens `ur-app`, clicks the session, and drives
   the editor through WebDriver.

   ```sh
   make e2e
   node --experimental-strip-types /tmp/ur-adhoc/check.ts
   ```

   The prompt "Reply with just the word pong" showed the user block and the agent block `pong`, and
   the sidebar showed Ox's session title. After closing and reopening the GUI, the same session was
   selected with the same two blocks. Killing the daemon showed "Connecting to <socket>" with the
   spinner; starting it again brought the thread back with the same two blocks, and a second prompt
   was answered `ping`, giving four blocks.
