# Pane grid

## Scope and coverage

The pane grid commit, "Show sessions and terminals in panes and tabs", against its plan
`plans/2026-09-25-014-pane-grid.md` and the Pane grid item in `todo.md`. Reviewed `Layout`,
`SessionPanel`, `TerminalPanel`, `PaneActions`, the watermark, `Tab`, `StatusMark`, `layout.ts`,
`App`, the sidebar, `actions.ts`, `TerminalPane`, the `hasSnapshot` change in `watch.ts`, the GUI
state file and the `layout` and `save_layout` commands, the tests in `layout.test.ts` and
`watch.test.ts`, the end-to-end tests in `panes.test.ts` and the tests the commit moved to tabs, the
harness's `shown()`, `panes()`, and `dragTab()`, and the documentation changes. Traced into dockview
8.3.1: `DockviewReact`'s lifecycle, `removePanel()` and empty groups, the buffered
`onDidLayoutChange`, and the overlay renderer behind `defaultRenderer="always"`. Also traced the
daemon's startup, which serves only after the first `session/list`, so a restore does not drop
session tabs against an incomplete snapshot, and `server_exited()`, which keeps sessions listed
while the server restarts.

Lenses: correctness, concurrency, resources, testing, comments, and documentation.

Besides tracing and the end-to-end suite, the size of hidden terminal tabs was measured with an
ad-hoc WebDriver script built on `TestEnvironment`. The pane's `+` and the workspace menu are native
menus, which WebDriver cannot drive, and were checked by tracing only.

## Findings

### Low

#### Correctness

- **OX-0009 A restored hidden terminal is sized to the whole dock area**
  (`app/src/components/TerminalPane.tsx:21`): a terminal restored as a tab that is not active has
  its PTY set to the size of the whole dock area until the tab is first shown. A full-screen program
  in it draws at the wrong size, then redraws when shown. The size guard's comment says a tab that
  is not active has no size, but dockview's `always` renderer hides such a tab with
  `visibility: hidden`, and its overlay keeps a size: its pane's size once shown, and dockview's
  default of 100% of the dock area before that. In the ad-hoc run, the restored hidden terminal's
  view measured 762×668 and `stty size` printed `44 95`, and showing it changed that to `42 97`. A
  counter in the guard's skip branch stayed at 0 on a fresh open and on a restore, so the guard
  never skipped a fit. Fit only while the tab is visible, using the panel API's `isVisible` and
  `onDidVisibilityChange`, and drop the size guard and its comment.

## Checks run

- `make check` — passed.
- `make e2e` — passed, 49 tests.
- Ad-hoc WebDriver script (not committed): a terminal tab hidden after being shown kept its pane's
  size (389×633); a restored terminal tab never shown measured 762×668 and ran at `44 95` until
  shown, then `42 97`. With a counter added to the size guard's skip branch, it stayed at 0.

## Verdict

The pane grid meets the plan and the todo item. Restoring, saving, closing gone tabs, and the
visible sessions follow dockview's lifecycle correctly, and unmounting on disconnect cannot save an
empty layout. One low severity issue is left open: the size of a restored terminal tab that has not
been shown yet.
