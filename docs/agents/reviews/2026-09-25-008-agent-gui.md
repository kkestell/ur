## Fixed

- **A removed session stays subscribed** (`app/src/store/sessions.ts:22`,
  `app/src-tauri/src/link.rs:83`): removing a workspace sends `session_removed`, and the store
  dropped the thread but kept the session in its `subscribed` set, as did the Link's desired set.
  Adding the workspace back lists the same saved sessions, and selecting one of them showed an empty
  thread with no `subscribe` sent, until the GUI restarted. The store and the Link now drop the
  session on `session_removed`. The end-to-end test
  `a session that comes back with its workspace shows its thread` covers it.
- **The editor's draft follows the selection** (`app/src/App.tsx:59`): `Session` rendered at the
  same position for every selected session, so a draft typed under one session, and its error
  message, appeared under the next one selected. `Session` is keyed by session ID. The end-to-end
  test `an editor draft does not follow the selection to another session` covers it.
- **A rejected prompt is lost** (`app/src/components/Editor.tsx:14`): the editor cleared the
  textarea before the response, so Enter during a running turn answered busy and discarded the
  prompt. A `busy` or `error` response, or a failed command, now restores the text unless something
  new was typed meanwhile. The end-to-end test
  `a prompt the daemon answers busy comes back to the editor` covers it.
- **`architecture.md` says `useSession` unsubscribes** (`docs/agents/architecture.md:362`): the
  paragraph said the hook unsubscribes when the last component unmounts, and the layout tree placed
  it in `hooks/` with a refcount, while the protocol list still had `unsubscribe`. The code never
  unsubscribes, as the plan decided, and the hook is in `store/sessions.ts`. The doc now says so,
  and `SessionState` is `ThreadState` as in the code.

## Findings

#### Correctness

- **OX-0005 A terminal attach error persists until the GUI restarts** (`app/src/App.tsx:14`):
  `terminalError` is set when `attach_terminal` fails and never cleared, so the Terminal row keeps
  showing the error after the daemon comes back. Reached only when the daemon goes away during the
  attach itself. Suggested fix: clear the error when the connection or the selection changes, or key
  the terminal view by connection.
