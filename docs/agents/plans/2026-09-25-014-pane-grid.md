# Pane grid

## Goal

Build the Pane grid section of `docs/agents/todo.md`, without the split button and split shortcuts.
Today the session area shows one selection: a thread with its session header, or a terminal with its
terminal header. The GUI state file holds that selection. When this is done:

- The session area is a dockview layout. Each pane is a dockview group, and each tab is a dockview
  panel for one agent session or one terminal.
- Each tab shows its kind (✦ for an agent session, `>_` for a terminal), its session title or
  terminal title, and, for an agent session, its status mark. Hovering a tab shows its Close Tab
  button in place of the status mark. Closing a tab leaves its session or terminal running.
- Each pane's header ends with `+`, which opens the new menu: New Session and New Terminal, in the
  workspace of the pane's active tab. The new session or terminal opens as a tab in that pane.
- Dragging a tab is dockview's own: dropping it on a pane's edge makes a new pane on that side, and
  dropping it on a pane's center moves the tab there. This is the only way to make a pane.
- Choosing a session or terminal in the sidebar activates its tab if it has one, wherever it is, and
  otherwise opens a tab in the active pane. The sidebar highlights the selection, which is the
  active tab.
- The session header and the terminal header are gone; the tab carries the kind, the title, and the
  pane's `+`.
- The GUI focuses every session shown as the active tab of a pane while the window has focus. The
  permission shortcuts answer the selection's pending requests only.
- A tab closes when its session is deleted or its workspace removed, or its terminal exits.
- The core saves the layout in the GUI state file on every change. Reopening the GUI restores it,
  dropping tabs whose session or terminal no longer exists.

## Decisions

### No split commands

The todo item's split button and its four shortcuts are dropped. A terminal can have only one tab,
so a split cannot copy the active tab, and an empty pane made by a split has nothing to close it.
Panes come only from dragging a tab onto a pane's edge. Update the todo section to match.

### One tab per session or terminal

The panel ID is `session:<session ID>` or `terminal:<terminal ID>`, from `tabId()`, and dockview
rejects a second panel with the same ID. `openTab(api, item, group?)` activates the existing panel
with `setActive()` or adds one with `params: item`, in `group` when given, else in the active pane.
With no panes, `addPanel()` makes one. One tab per terminal matches the Link, which keeps one
terminal attachment per terminal.

### Tabs stay mounted

`defaultRenderer="always"`, so a tab that is not active keeps its component mounted: a terminal
stays attached and keeps writing to its xterm.js view, and a thread keeps its scroll position and
the editor its draft. Moving a tab between panes does not remount it. A hidden terminal's container
has no size, and `fit.fit()` would shrink the terminal to one row and resize the PTY, so the
`ResizeObserver` fits only when the container's width and height are both nonzero.

### The selection is the active tab

The selection is the session or terminal of dockview's active panel, tracked from
`onDidActivePanelChange` in `App` state. It is `TabItem | null`. The sidebar highlights it, and only
the selection's `SessionPanel` installs the permission shortcuts' `keydown` listener, using the
panel API's `isActive` and `onDidActiveChange`. The saved selection goes away: dockview's serialized
layout holds each pane's active tab and the active pane.

### Visible sessions

`visibleSessions(api)` is the session of each pane's active tab. `Layout` keeps it in state, updated
on `onDidLayoutChange` and `onDidActivePanelChange`, and calls `setVisible()` with those in the
watch state, so the daemon is never asked to focus a session the sidebar does not show. The effect
depends on the joined session IDs, so watch events that change nothing do not resend it.

### Closing tabs whose session or terminal is gone

`goneTabs(items, watch, previous?)` returns the tabs to close. Without `previous`, when the layout
is restored, it returns every tab whose session or terminal is not in `watch`. With `previous`, it
returns only those that were in `previous` and are not in `watch`. A terminal opened by New Terminal
gets its tab when `open_terminal` answers, which can be before its `terminal_changed` arrives, so a
tab whose terminal has not appeared yet stays open. Until its summary arrives, the panel renders
nothing and the tab shows no title. `Layout` runs it on each watch change with the previous watch
state held in a ref, and closes the tabs it returns with `removePanel()`.

A disconnect clears the watch state, so `App` unmounts `Layout` while disconnected, as it hides
everything today. Reconnecting mounts it again, which restores the saved layout against the new
watch snapshot. This covers a daemon restart, which ends every terminal.

### Restoring the layout

`WatchState` gains `hasSnapshot`, set by `watch_snapshot` and cleared by a disconnect. `App` renders
`Layout` only when connected, with the watch snapshot, and with the saved layout read. `onReady`
calls `api.fromJSON()` on the saved layout, closes `goneTabs()` without `previous`, and only then
registers the `onDidLayoutChange` listener that saves, so a partial layout is not saved. The
listener is disposed in `Layout`'s effect cleanup, before dockview is torn down, so unmounting does
not save an empty layout. A layout that `fromJSON()` rejects is a bug and throws.

### GUI state file

`Saved { selection }` becomes `Saved { layout: Option<serde_json::Value> }`, holding dockview's
`SerializedDockview` as is; the core never reads inside it. The `selection` and `select` commands
become `layout`, which returns the saved layout or `null`, and `save_layout(layout)`, which writes
it on every layout change, including while a pane border is dragged. `Selection` and its binding
`app/src/ipc/bindings/Selection.ts` are deleted. Delete `gui.json` after this change.

### Tabs and the pane header

- `Tab` is the tab component for every panel. It reads the watch state for the session title or
  terminal title. `StatusMark` moves to its own file so the sidebar and the tab share it. The Close
  Tab button calls the panel API's `close()`, which changes only the layout.
- `PaneActions` is the `rightHeaderActionsComponent`: `+` when the pane has an active tab. Its click
  calls `showNewMenu(workspace, onOpen)`, whose items call `newSession()` and `newTerminal()` with
  an `onOpen` that opens the new tab in that pane. The workspace menu's New Session and New Terminal
  open in the active pane.
- `newSession()`, `newTerminal()`, and `showWorkspaceMenu()` take `onOpen: (item: TabItem) => void`
  in place of `onSelect`.
- `watermarkComponent` shows the existing empty states when no tab is open: No workspaces with Add
  Workspace, or Select a session.

### Styling

Import dockview's stylesheet and use its dark theme, with its CSS variables set in `styles.css` to
the app's existing colors, so tabs and pane borders match the sidebar. The `.session-header` and
`.terminal-header` rules are removed.

## Naming

- **Pane** — a dockview group holding tabs. The active pane receives sidebar choices.
- **Tab** — a dockview panel for one agent session or terminal. Closing it changes only the layout.
  `Tab` is also its tab component.
- **Layout** — the dockview arrangement of panes and tabs, saved in the GUI state file. `Layout` is
  the component that holds `DockviewReact`.
- **Selection** — changes meaning: the session or terminal of the active tab, highlighted in the
  sidebar. It is no longer saved separately.
- **`TabItem`** — the session or terminal one tab shows: `{ type: "session", session }` or
  `{ type: "terminal", terminal }`. It is the panel's params.
- **New menu** — the native menu from a pane's `+`: New Session and New Terminal. `showNewMenu()` in
  code.
- **Visible session** — a session shown as the active tab of a pane.
- **Close Tab** — the button a tab shows on hover.
- Session header and terminal header are removed.

## Test plan

Webview unit tests:

- `app/src/layout.test.ts`, `tabs_close_when_their_session_or_terminal_is_gone`, table-driven over
  `goneTabs()`: restoring drops a missing session and a missing terminal and keeps present ones; a
  live change closes a deleted session and an exited terminal; a live change keeps a terminal tab
  whose terminal has not appeared yet.
- `app/src/store/watch.test.ts`, `has_snapshot_follows_the_connection`: `hasSnapshot` is set by the
  watch snapshot and cleared by a disconnect.

End-to-end tests. A tab that is not active stays mounted, hidden with `visibility: hidden`, so every
harness helper looks only at shown elements, through a `shown()` function `Gui.connect()` installs
in the webview. `Gui.panes()` lists each pane's tab labels, marking the active tab and the active
pane, and `Gui.dragTab()` sends the drag events dockview listens for, since WebDriver cannot drive
native drag and drop. `Gui.showTerminal()` keeps working: clicking the terminal row opens its tab,
and a reopened GUI restores the tab from the layout.

New tests in `app/e2e/panes.test.ts`, most starting from the terminal's tab in the left pane and a
session titled `tallies` in the right one, made by dragging its tab to the pane's right edge:

- `dragging a tab to a pane's edge makes a new pane`.
- `dragging a tab to a pane's center moves the tab there`.
- `choosing a session or terminal with a tab activates that tab in its pane`: and the sidebar
  highlights it.
- `a session chosen in the sidebar opens in the active pane`.
- `the layout and each pane's active tab survive closing and reopening the GUI`.
- `Close Tab leaves its terminal running`: the terminal row stays, and clicking it reopens the tab
  with the earlier output.
- `a terminal tab keeps its size while another tab is shown`: `stty size` before and after.
- `a session's tab shows its status mark`.
- `a session shown in a pane that is not active does not become unread`: `ur ls` after the turn.
- `the permission shortcuts answer only the active tab's session`: two sessions in two panes, each
  with a pending request.

Changed tests, for guarantees this change moves:

- `each session's tab keeps its own editor draft` replaces
  `an editor draft does not follow the selection to another session`: the draft is still there when
  its tab is shown again.
- `a session's tab shows the session title` replaces `the session header shows the session title`.
- `the session header's + creates a session in its workspace and selects it` is deleted with the
  session header. The pane's `+` opens a native menu, which WebDriver cannot drive.
- The terminal title test reads the tab instead of the terminal header, and the delete and exit
  tests also check that the tab closes.

Run `make e2e` at the end, since this finishes a top-level item.

The ad-hoc check is the todo item's check: a terminal running `npm run dev` in one pane next to an
agent session in another, made by dragging a tab to a pane's edge. Close the GUI, reopen it, and
both are restored in the same layout, with the same active tabs. Also check by hand: the sidebar
activates an existing tab in another pane; `+` opens in its own pane; Close Tab leaves the terminal
listed and running; a hidden terminal tab keeps its size when shown again; deleting a session and
closing a terminal close their tabs; the permission shortcuts answer only the active tab's session.
